# Vidi Web - Deployment Guide

This guide provides step-by-step instructions for deploying the **Vidi Web** application to production environments.

---

## 📋 Architecture & Tech Stack

- **Framework**: [Next.js 16](https://nextjs.org/) (App Router, Turbopack, React 19)
- **Styling**: [Tailwind CSS v4](https://tailwindcss.com/)
- **Authentication**: [Supabase Auth](https://supabase.com/docs/guides/auth) (Google OAuth 2.0 with SSR session cookies)
- **Database**: [Supabase PostgreSQL](https://supabase.com/docs/guides/database) with Row-Level Security (RLS)
- **Caching**: [Upstash Redis](https://upstash.com/) (Serverless REST client for TMDB API response caching)
- **Content & Metadata**: [The Movie Database (TMDB) API](https://developer.themoviedb.org/reference/intro/getting-started)
- **Video Embeds**: [VidSrc](https://vidsrc.to/)

---

## 🔑 Environment Variables Reference

Before deploying, prepare the following environment variables. You can find a template in [`.env.example`](.env.example).

| Variable Name | Scope | Description | Example Format |
|---|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Public (Client + Server) | URL of your Supabase project instance | `https://xyzcompany.supabase.co` |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Public (Client + Server) | Supabase Publishable / Anon public API key | `sb_publishable_...` or `eyJhbGciOi...` |
| `UPSTASH_REDIS_REST_URL` | Secret (Server only) | REST URL endpoint for your Upstash Redis database | `https://xxxx-xxxx-12345.upstash.io` |
| `UPSTASH_REDIS_REST_TOKEN` | Secret (Server only) | REST token for authenticating with Upstash Redis | `gQAAAAAA...` |
| `TMDB_API_KEY` | Secret (Server only) | TMDB API Read Access Token (v4 auth Bearer token) | `eyJhbGciOi...` |
| `NODE_ENV` | System | Environment mode (`production` or `development`) | `production` |

> ⚠️ **Important**: Never commit `.env` or `.env.local` to source control. Only commit [`.env.example`](.env.example).

## 🛠️ Third-Party Services Setup

### 1. Supabase Database & Auth

#### A. Create Database Schema
1. Open your [Supabase Dashboard](https://supabase.com/dashboard) and select your project.
2. Navigate to **SQL Editor** and run the following script to create the `watchlists` table and configure Row Level Security (RLS):

```sql
-- Create watchlists table
CREATE TABLE IF NOT EXISTS public.watchlists (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
    movie_id BIGINT NOT NULL,
    title TEXT NOT NULL,
    poster_path TEXT,
    release_year TEXT,
    genre TEXT,
    vote_average NUMERIC(3, 1),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT timezone('utc'::text, now()) NOT NULL,
    CONSTRAINT watchlists_user_movie_unique UNIQUE (user_id, movie_id)
);

-- Create index for faster querying by user
CREATE INDEX IF NOT EXISTS idx_watchlists_user_id ON public.watchlists(user_id);

-- Enable Row Level Security (RLS)
ALTER TABLE public.watchlists ENABLE ROW LEVEL SECURITY;

-- Policy: Users can view only their own watchlist items
CREATE POLICY "Users can view their own watchlist"
ON public.watchlists
FOR SELECT
USING (auth.uid() = user_id);

-- Policy: Users can insert their own watchlist items
CREATE POLICY "Users can insert into their own watchlist"
ON public.watchlists
FOR INSERT
WITH CHECK (auth.uid() = user_id);

-- Policy: Users can delete their own watchlist items
CREATE POLICY "Users can delete from their own watchlist"
ON public.watchlists
FOR DELETE
USING (auth.uid() = user_id);
```

#### B. Configure Google OAuth Provider
1. Go to **Authentication > Providers > Google**.
2. Toggle **Enable Google provider**.
3. Create an OAuth 2.0 Client in the [Google Cloud Console](https://console.cloud.google.com/apis/credentials):
   - **Authorized JavaScript origins**: `https://<your-project-id>.supabase.co`
   - **Authorized redirect URI**: `https://<your-project-id>.supabase.co/auth/v1/callback`
4. Copy the **Client ID** and **Client Secret** from Google Cloud into the Supabase Google Provider settings.

#### C. Configure Redirect URLs in Supabase
In Supabase Dashboard under **Authentication > URL Configuration**:
- **Site URL**: `https://<your-production-domain>` (e.g. `https://vidi.yourdomain.com`)
- **Redirect URLs**: Add the following URLs:
  - `https://<your-production-domain>/auth/callback`
  - `http://localhost:3000/auth/callback` (for local development)

---

### 2. Upstash Redis (Caching)

1. Log in to [Upstash Console](https://console.upstash.com/).
2. Create a new **Redis** database (select regional or global based on your server location).
3. Under the **Details** page, scroll down to **REST API**.
4. Select the **`.env`** tab or copy:
   - `UPSTASH_REDIS_REST_URL`
   - `UPSTASH_REDIS_REST_TOKEN`

---

### 3. TMDB API Key

1. Register an account on [The Movie Database (TMDB)](https://www.themoviedb.org/).
2. Navigate to **Account Settings > API**.
3. Request an API key (choose Developer/Personal).
4. Copy the **API Read Access Token (v4 auth)**. This token is used in Bearer authorization headers and should be set as `TMDB_API_KEY`.

## 🚀 Deployment Targets

### Option 1: Vercel (Recommended)

Vercel is the native hosting platform for Next.js and provides zero-configuration deployments.

#### Method A: Deploy via GitHub Integration
1. Push your repository to GitHub / GitLab / Bitbucket.
2. Go to [Vercel Dashboard](https://vercel.com/dashboard) and click **Add New > Project**.
3. Import the `vidi-web` repository.
4. In the **Configure Project** screen:
   - **Framework Preset**: `Next.js`
   - **Root Directory**: `./`
   - **Build Command**: `next build` (or leave default)
   - **Output Directory**: `.next` (or leave default)
   - **Install Command**: `npm install`
5. Expand **Environment Variables** and add:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
   - `UPSTASH_REDIS_REST_URL`
   - `UPSTASH_REDIS_REST_TOKEN`
   - `TMDB_API_KEY`
6. Click **Deploy**.

#### Method B: Deploy via Vercel CLI
```bash
# Install Vercel CLI globally
npm i -g vercel

# Link and deploy
vercel

# Add environment variables to production
vercel env add NEXT_PUBLIC_SUPABASE_URL production
vercel env add NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY production
vercel env add UPSTASH_REDIS_REST_URL production
vercel env add UPSTASH_REDIS_REST_TOKEN production
vercel env add TMDB_API_KEY production

# Deploy to production
vercel --prod
```

### Option 2: Self-Hosted VPS / Linux VM (Node.js + PM2 + Nginx)

#### 1. System Requirements
- Ubuntu 22.04 LTS or newer
- Node.js 20.x or 22.x LTS
- PM2 process manager
- Nginx

#### 2. Install Dependencies
```bash
# Install Node.js 20.x LTS
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs nginx git

# Install PM2 globally
sudo npm install -g pm2
```

#### 3. Clone and Build Project
```bash
cd /var/www
git clone https://github.com/your-username/vidi-web.git
cd vidi-web

# Install project dependencies
npm ci

# Create production environment file
cp .env.example .env.local
nano .env.local # Fill in your production keys

# Build the Next.js production bundle
npm run build
```

#### 4. Manage with PM2
```bash
# Start Next.js with PM2
pm2 start npm --name "vidi-web" -- start -- -p 3000

# Ensure PM2 restarts on server reboot
pm2 save
pm2 startup
```

#### 5. Configure Nginx Reverse Proxy
Create `/etc/nginx/sites-available/vidi-web`:

```nginx
server {
    listen 80;
    server_name vidi.yourdomain.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-Host $host;
        proxy_cache_bypass $http_upgrade;
    }
}
```

Enable site and configure SSL using Certbot:
```bash
sudo ln -s /etc/nginx/sites-available/vidi-web /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx

# Install Let's Encrypt SSL
sudo apt-get install -y certbot python3-certbot-nginx
sudo certbot --nginx -d vidi.yourdomain.com
```

> ⚠️ **Note on `X-Forwarded-Host`**: The auth callback route (`app/auth/callback/route.ts`) checks `request.headers.get('x-forwarded-host')` to handle redirects correctly behind reverse proxies. Ensure your reverse proxy forwards this header.

### Option 3: Docker Deployment

If you prefer containerized deployment (e.g. AWS ECS, Google Cloud Run, Railway, or VPS with Docker):

#### 1. Enable Standalone Output in `next.config.ts`
Edit `next.config.ts` to enable Next.js standalone output:

```typescript
import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  output: "standalone",
};

export default nextConfig;
```

#### 2. Create `Dockerfile`
Create a `Dockerfile` in the root of your project:

```dockerfile
# Stage 1: Dependencies
FROM node:20-alpine AS deps
RUN apk add --no-cache libc6-compat
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci

# Stage 2: Builder
FROM node:20-alpine AS builder
WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY . .

# Build-time environment variables for Next.js public client variables
ARG NEXT_PUBLIC_SUPABASE_URL
ARG NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY
ENV NEXT_PUBLIC_SUPABASE_URL=$NEXT_PUBLIC_SUPABASE_URL
ENV NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=$NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY

ENV NEXT_TELEMETRY_DISABLED=1
RUN npm run build

# Stage 3: Runner
FROM node:20-alpine AS runner
WORKDIR /app

ENV NODE_ENV=production
ENV PORT=3000
ENV HOSTNAME="0.0.0.0"
ENV NEXT_TELEMETRY_DISABLED=1

RUN addgroup --system --gid 1001 nodejs
RUN adduser --system --uid 1001 nextjs

COPY --from=builder /app/public ./public
COPY --from=builder --chown=nextjs:nodejs /app/.next/standalone ./
COPY --from=builder --chown=nextjs:nodejs /app/.next/static ./.next/static

USER nextjs

EXPOSE 3000

CMD ["node", "server.js"]
```

#### 3. Build and Run Container
```bash
# Build Docker image
docker build \
  --build-arg NEXT_PUBLIC_SUPABASE_URL="https://your-project.supabase.co" \
  --build-arg NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY="your-key" \
  -t vidi-web:latest .

# Run Docker container
docker run -d \
  -p 3000:3000 \
  -e UPSTASH_REDIS_REST_URL="https://your-instance.upstash.io" \
  -e UPSTASH_REDIS_REST_TOKEN="your-token" \
  -e TMDB_API_KEY="your-tmdb-key" \
  --name vidi-web \
  vidi-web:latest
```

## ✅ Post-Deployment Verification Checklist

Once deployed, verify each feature in production:

1. **Home Page & Metadata (`/`)**:
   - Verify that trending movies and TV shows are displayed.
   - Verify that backdrop hero carousel renders images from TMDB (`image.tmdb.org`).
2. **Search Feature (`/movies/[category]`)**:
   - Open search or browse by category (Trending, Popular, Top Rated, Upcoming).
   - Ensure dynamic results load and pagination works.
3. **Movie Detail View (`/movie/[id]`)**:
   - Click any title to check poster, cast, overview, and trailer playback.
4. **Google Authentication Flow (`/login`)**:
   - Click "Sign in with Google".
   - Confirm Google account picker opens and redirects to `/auth/callback`, then back to the intended page.
   - Verify that user profile avatar, name, and email show up on `/profile`.
5. **Watchlist Functionality**:
   - Click "Add to Watchlist" on a movie.
   - Confirm button toggles to "In Watchlist".
   - Navigate to `/profile/watchlist` and confirm the movie appears in the saved list.
   - Remove the movie from the watchlist and verify it disappears.
6. **Video Player (`/watch/[type]/[id]`)**:
   - Navigate to a movie or episode watch page.
   - Confirm the VidSrc iframe player embeds without CORS or CSP blocking.
7. **Performance & Caching**:
   - Check Upstash Redis Console to confirm keys such as `trending:movie`, `details:movie:*` are populated.

## 🔍 Troubleshooting

| Issue | Likely Cause | Solution |
|---|---|---|
| **Google Sign-In fails or redirects to `/login?error=auth_error`** | Callback URL mismatch in Supabase or Google Console | Verify that `https://<domain>/auth/callback` is added in Supabase **Redirect URLs** and that Supabase's callback URL is in Google Cloud Console. |
| **Movie data / Trending list empty or 500 error** | Invalid or missing `TMDB_API_KEY` | Ensure `TMDB_API_KEY` contains the v4 Read Access Bearer token (not just the short v3 API key). |
| **Watchlist actions fail or user receives "You must be logged in"** | Session cookies not passing across domains/proxies | Ensure `X-Forwarded-Proto: https` is sent by reverse proxy and HTTPS is properly enabled. Supabase SSR cookies require secure context. |
| **Redis connection errors in server logs** | Incorrect Upstash credentials | Verify `UPSTASH_REDIS_REST_URL` (starts with `https://`) and `UPSTASH_REDIS_REST_TOKEN`. |
| **Images failing to load from TMDB** | External domain image configuration | TMDB images (`image.tmdb.org`) are served as standard `<img>` tags or need domain permissions if using Next.js `<Image />`. |
